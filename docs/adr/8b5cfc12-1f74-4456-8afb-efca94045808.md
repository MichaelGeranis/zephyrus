# ADR: Project and Artifact Deletion

## Summary
Implement cascading deletion functionality for Projects, Features, and Artifacts using hard deletion with confirmation dialogs. The architecture leverages existing repositories with new delete methods, adds deletion endpoints to existing controllers, and implements confirmation UI components. Deletion operations cascade down the hierarchy (Project → Features → Artifacts) while maintaining referential integrity through proper ordering of database operations.

## New Components
- **Application Layer:**
  - `DeleteProjectUseCase` - Orchestrates project deletion with cascading logic
  - `DeleteFeatureUseCase` - Orchestrates feature deletion with cascading logic
  - `DeleteArtifactUseCase` - Orchestrates single artifact deletion
- **Web Layer:**
  - `DeleteConfirmationModal` - Reusable confirmation dialog component
  - `DeleteButton` - Consistent delete button with loading states

## Database Changes
No schema changes required. Existing foreign key relationships will handle cascading through application logic:
- `Artifacts.FeatureId` → `Features.Id`
- `Features.ProjectId` → `Projects.Id`
- `TaskItems.FeatureId` → `Features.Id`
- `AgentInvocations.FeatureId` → `Features.Id`
- `PipelineEvents.FeatureId` → `Features.Id`

Migration: Not applicable (no schema changes needed)

## API Contracts

### `DELETE /api/projects/{id}`
- **Request:** None (path parameter only)
- **Response:** 
  ```json
  {
    "deletedProjectsCount": 1,
    "deletedFeaturesCount": 5,
    "deletedArtifactsCount": 23
  }
  ```
- **Status codes:** 200 OK, 404 Not Found, 500 Internal Server Error

### `DELETE /api/features/{id}`
- **Request:** None (path parameter only)
- **Response:**
  ```json
  {
    "deletedFeaturesCount": 1,
    "deletedArtifactsCount": 8
  }
  ```
- **Status codes:** 200 OK, 404 Not Found, 500 Internal Server Error

### `DELETE /api/artifacts/{id}`
- **Request:** None (path parameter only)
- **Response:**
  ```json
  {
    "deletedArtifactsCount": 1
  }
  ```
- **Status codes:** 200 OK, 404 Not Found, 500 Internal Server Error

### `GET /api/projects/{id}/deletion-preview`
- **Request:** None (path parameter only)
- **Response:**
  ```json
  {
    "projectTitle": "Example Project",
    "featuresCount": 5,
    "artifactsCount": 23,
    "warnings": []
  }
  ```
- **Status codes:** 200 OK, 404 Not Found

### `GET /api/features/{id}/deletion-preview`
- **Request:** None (path parameter only)
- **Response:**
  ```json
  {
    "featureTitle": "User Authentication",
    "artifactsCount": 8,
    "warnings": []
  }
  ```
- **Status codes:** 200 OK, 404 Not Found

## External Dependencies
None required. Implementation uses existing EF Core capabilities and current UI component patterns.

## Sequence Diagram
1. User clicks delete button on Project/Feature/Artifact page
2. Frontend calls GET `/api/{entity}/{id}/deletion-preview` endpoint
3. Backend queries database for counts of child entities
4. Frontend displays `DeleteConfirmationModal` with preview data
5. User confirms deletion
6. Frontend calls DELETE `/api/{entity}/{id}` endpoint
7. Backend executes `Delete{Entity}UseCase`
8. Use case deletes child entities in correct order (Artifacts → TaskItems → Features → Project)
9. Backend commits transaction and returns deletion summary
10. Frontend redirects to parent page or dashboard
11. UI updates to remove deleted entities from all views

## Risks & Open Questions
- Performance impact when deleting large projects with hundreds of features/artifacts.
- Need to ensure proper transaction boundaries to maintain data integrity during cascading deletes.
- Should implement soft delete in the future for audit trails and recovery capabilities. (No need).
- Consider impact on active pipeline operations or GitHub integrations (noted as future enhancement).
- Potential race conditions if deletion occurs while agents are actively processing the same entities. (Will be addressed in the future).
