# ADR: Project and Artifact Deletion

## Summary
Implement cascading deletion functionality for Projects, Features, and Artifacts using Entity Framework's cascade delete configuration combined with explicit use case classes for business logic orchestration. This approach ensures data integrity while providing clear confirmation dialogs showing the scope of deletions before execution.

## New Components
- `DeleteProjectUseCase` (Application layer) - Orchestrates project deletion with cascading effects
- `DeleteFeatureUseCase` (Application layer) - Handles feature deletion with artifact cascading
- `DeleteArtifactUseCase` (Application layer) - Manages individual artifact deletion
- `DeletionSummaryDto` (Api layer) - DTO for deletion confirmation information
- `DeleteProjectController` action (Api layer) - REST endpoint for project deletion
- `DeleteFeatureController` action (Api layer) - REST endpoint for feature deletion  
- `DeleteArtifactController` action (Api layer) - REST endpoint for artifact deletion
- `ConfirmationDialog` (Web layer) - Reusable React component for deletion confirmations
- `useDeletion` hook (Web layer) - Custom React hook for deletion operations

## Database Changes
No schema changes required. Existing foreign key relationships between Projects → Features → Artifacts will be configured with CASCADE DELETE in Entity Framework:
- `Feature.ProjectId` → `Project.Id` (CASCADE)
- `Artifact.FeatureId` → `Feature.Id` (CASCADE)

Migration name suggestion: `ConfigureCascadeDeleteRelationships`

## API Contracts

### `DELETE /api/projects/{id}/deletion-summary`
- **Request:** Empty body
- **Response:** `{ "projectName": "string", "featureCount": 0, "artifactCount": 0 }`
- **Status codes:** 200 OK, 404 Not Found

### `DELETE /api/projects/{id}`
- **Request:** Empty body
- **Response:** `{ "message": "Project deleted successfully" }`
- **Status codes:** 200 OK, 404 Not Found, 500 Internal Server Error

### `DELETE /api/features/{id}/deletion-summary`
- **Request:** Empty body
- **Response:** `{ "featureName": "string", "artifactCount": 0 }`
- **Status codes:** 200 OK, 404 Not Found

### `DELETE /api/features/{id}`
- **Request:** Empty body
- **Response:** `{ "message": "Feature deleted successfully" }`
- **Status codes:** 200 OK, 404 Not Found, 500 Internal Server Error

### `DELETE /api/artifacts/{id}`
- **Request:** Empty body
- **Response:** `{ "message": "Artifact deleted successfully" }`
- **Status codes:** 200 OK, 404 Not Found, 500 Internal Server Error

## External Dependencies
No new external dependencies required. Leveraging existing Entity Framework Core cascade delete functionality and current React/Next.js stack.

## Sequence Diagram
1. User clicks delete button on entity detail page
2. Frontend calls GET deletion-summary endpoint to retrieve impact information
3. Confirmation dialog displays summary (e.g., "Delete project 'X' and 3 features with 12 artifacts?")
4. User confirms deletion
5. Frontend calls DELETE endpoint for the entity
6. Use case class retrieves entity with related data using EF Include()
7. Use case validates entity exists and can be deleted
8. Repository.Delete() called - EF cascade delete handles related entities
9. Database transaction commits, removing all related records
10. Success response returned to frontend
11. Frontend redirects to appropriate parent page or dashboard

## Risks & Open Questions
- Potential foreign key constraint violations if deletion order is incorrect
- Long-running deletion operations for projects with many artifacts may timeout
- Race conditions if multiple users attempt to delete related entities simultaneously
- No consideration for external system cleanup (GitHub repos, deployed resources)
- Missing safeguards for large-scale deletions that could impact system performance
