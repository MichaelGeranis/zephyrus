# ADR: Delete Projects, Features, and Artifacts

## Summary
Implement hard deletion capabilities for projects, features, and artifacts using cascading delete patterns through Entity Framework relationships and dedicated use cases for each entity type. The approach leverages existing repository patterns and adds new delete-specific use cases that handle foreign key constraints automatically through EF Core cascade delete configurations.

## New Components
- `DeleteProjectUseCase` class (Application layer)
- `DeleteFeatureUseCase` class (Application layer)  
- `DeleteArtifactUseCase` class (Application layer)
- `ProjectsController.Delete()` method (Api layer)
- `FeaturesController.Delete()` method (Api layer)
- `ArtifactsController.Delete()` method (Api layer)
- Client-side confirmation modal components (Web layer)
- Delete button components for each entity type (Web layer)

## Database Changes
- Modify existing foreign key relationships to use CASCADE delete:
  - `Features.ProjectId` → `Projects.Id` (ON DELETE CASCADE)
  - `Artifacts.FeatureId` → `Features.Id` (ON DELETE CASCADE)
  - `PipelineSteps.ProjectId` → `Projects.Id` (ON DELETE CASCADE)
- Migration name: `20250XXX_AddCascadeDeleteConstraints`

## API Contracts

### `DELETE /api/projects/{id}`
- **Request:** Empty body
- **Response:** Empty body
- **Status codes:** 204 (No Content), 404 (Not Found), 409 (Conflict)

### `DELETE /api/features/{id}`
- **Request:** Empty body
- **Response:** Empty body  
- **Status codes:** 204 (No Content), 404 (Not Found), 409 (Conflict)

### `DELETE /api/artifacts/{id}`
- **Request:** Empty body
- **Response:** Empty body
- **Status codes:** 204 (No Content), 404 (Not Found), 409 (Conflict)

## External Dependencies
- No new external dependencies required
- Leverages existing Entity Framework Core cascade delete functionality
- Uses existing repository pattern interfaces

## Sequence Diagram
1. User clicks delete button in UI for any entity type
2. Frontend displays confirmation modal with entity details
3. User confirms deletion action
4. Frontend sends DELETE request to appropriate API endpoint
5. Controller invokes corresponding delete use case
6. Use case retrieves entity via repository to verify existence
7. Use case calls repository Delete method
8. Repository removes entity from DbContext
9. DbContext.SaveChanges() triggers cascade deletes via EF Core
10. Database automatically removes dependent entities
11. Use case returns success to controller
12. Controller returns 204 No Content
13. Frontend removes entity from UI state and closes modal

## Risks & Open Questions
- EF Core cascade deletes may not handle complex dependency graphs if circular references exist
- Need to verify that deleting projects with active pipeline states doesn't cause data inconsistencies
- Should implement transaction rollback if GitHub repository cleanup fails during project deletion
- Consider adding pre-deletion validation to prevent deletion of entities currently being processed by AI agents
- Potential performance impact when deleting projects with large numbers of features and artifacts
